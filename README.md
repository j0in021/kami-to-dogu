このリポジトリの初期実装はAIが作成した学習用の完成見本です。本人の学習記録・独力で作った成果とは区別します。

## 架空の発注テーマ

発注者は、日常使いの文房具を扱う架空の小さな店「紙と道具」。実店舗で販売してきた方眼ノート・細字ペン・布製ポーチを、初めて自社サイトで販売したい。注文前に色と形だけでなく、使う場面、紙・布の質感、送料を確かめられるページを依頼された、という設定。

9/25の制作範囲は、商品一覧、商品詳細、数量の選択、カート、届け先入力、模擬決済、店側ログイン、注文受付・お断り・発送完了の記録まで。実際の課金・発送は含まない。見本の写真・価格・送料条件は架空のもので、接続後にはDB内の商品データと表示を一致させる。

## 実装の接続手順

現在はSupabaseとVercelのアカウントが未作成。ローカルUIとサーバーコード・SQLは用意済みだが、**注文保存・ログイン・デプロイの実接続は未確認**。既存の写真入りHTMLを保つため、この版はNext.jsではなく静的ページ＋Vercel Functionsで組んだ。9/24のNext.js学習成果とは別に扱う。

1. Supabaseにこの練習用の新しいプロジェクトを作る。実店舗や「まるの森。」のDBを使わない。
2. [setup.sql](supabase/setup.sql)をSQL Editorで実行する。3商品のデモデータ、注文・注文明細・管理者表、権限、価格再計算と状態遷移のDB関数が作られる。
3. Supabase Authで店舗担当者のテストアカウントを1つ作り、そのユーザーIDをsetup.sql末尾のadmin_users追加文へ入れて別途実行する。Authユーザーだけでは管理権限にならない。
4. VercelでこのdesignフォルダをRoot Directoryとしてデプロイする。環境変数SUPABASE_URL、SUPABASE_PUBLISHABLE_KEY、SUPABASE_SECRET_KEYを設定する。SECRET_KEYはサーバーだけで使い、公開ファイルへ書かない。
5. 公開URLのトップで模擬決済し、注文番号を記録する。/adminでログインし、その注文を受付→発送完了へ変更する。別の注文では未対応→お断りを試す。未ログインで/api/admin-ordersを読むと401、一般ユーザーでは403になることを確認する。

実際の課金APIはなく、「決済する（デモ）」は商品IDと数量だけをサーバーへ送る。DB関数が商品価格を読み直して注文を原子的に保存する。同じ注文キーを再送しても同じ注文を返す。状態変更は未対応→受付/お断り、受付→発送完了だけを許す。顧客入力はexample.comのテスト用メールと「架空」で始まる住所に限定する。

ローカル確認はこのフォルダで `node dev-server.js` を実行し、http://127.0.0.1:4173/ と /admin を開く。環境変数がなければカートと確認画面まで動き、注文保存とログインは未設定表示になる。`node --test tests/api.test.js` は価格改ざん値の不採用と管理者権限のサーバー側判定をモックで確認する。実DBでのトランザクション・RLS・Vercel動作は接続後に別途検証する。

公式資料：[Supabase Data API保護](https://supabase.com/docs/guides/api/securing-your-api)、[APIキーの扱い](https://supabase.com/docs/guides/getting-started/api-keys)、[DB関数](https://supabase.com/docs/guides/database/functions)。

## 写真の配置と役割

| 場所 | 写真 | 伝えること |
|---|---|---|
| ファーストビュー | ノート・ペン・ポーチのある机 | 商品が暮らしの中にある様子と店の雰囲気 |
| 商品一覧 | 各商品を1点ずつ写した3枚 | 色・形を見比べて商品を選ぶ |
| 一覧の次の段 | ノートに書く手元 | 実際の使い方とサイズ感 |
| 商品詳細 | 表紙の正面、紙と製本の接写、使用場面、他の道具と並べた写真 | 購入前に外観、質感、使い方を確かめる |
| 素材紹介 | 俯瞰の文具写真と方眼紙の接写 | 紙・布の質感と組み合わせ方 |
| 注文内容 | 商品の小さな写真 | 何を何点買うか取り違えない |

写真配置は[Speedianceの個別商品ページ](https://jp.speediance.com/products/gym-monster-2)にある複数の製品画像と用途別の説明画像、[Baronfigの個別ノートページ](https://baronfig.com/products/confidant-hardcover-notebook?variant=35638866124)にある色・仕様選択と使用場面・素材の説明を参考にした。レイアウトと写真は模写せず、この架空店舗用に構成した。

## 見た目と確認

- 鮮やかなオレンジ、黒、白を主役にする。面と写真は角を立て、ボタン・小さな選択部品は完全な円またはピル形に統一。中途半端な角丸と左罫線アクセントカードを使わない。
- アイコンはLucide系の線画SVG。絵文字を使わない。
- 画像7枚が全て読み込まれること、PC幅1440px・スマホ幅375pxで横スクロールが出ないことをChromeで確認した。
- 入場前の同意はブラウザのタブ内で保持し、同意後にだけ店の画面を表示する。同意しない場合は入口へ戻れる。これは案内画面であり、アクセス制御や法的責任の全面免除を保証する仕組みではない。
- 9/23の住所検索UIも入口ページに残してある。ECのデザインとは異なる課題として扱う。
- [Figma下書き](https://www.figma.com/design/3RnVmAJHoJDcF2noUPOn3M)は途中で、今回の正本ではない。
